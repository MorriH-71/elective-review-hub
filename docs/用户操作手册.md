# 用户操作手册（v2.0）

## 启动

```bash
python3 -m pip install -r requirements.txt
python3 run.py
```

浏览器打开 `http://127.0.0.1:8765/`。首次启动会自动建库并载入 126 行虚构演示申请：14 行在申请阶段被驳回，112 行被受理（其中 100 条系统自动通过、12 条进入人工审核队列）。
如果只是想看界面，直接双击根目录 `preview.html`，无需安装任何依赖。

界面右上角可切换身份：

- **教务员小林**：日常审核、导入、导出
- **系统管理员**：额外可以启停规则、人工复核与改判系统自动通过的结果、批量确认复核
- **只读访客**：只能看，所有审核与复核按钮禁用

## 一、先看懂三个去向

| 去向 | 会出现在哪里 | 需要人做什么 |
|---|---|---|
| 申请阶段驳回 | 「申请受理」页的驳回台账 | 申请人修正后重交；教务人员不用处理 |
| 系统自动通过 | 审核工作台，状态「已通过」+ 蓝色「系统」标记 | 管理员可选择抽查复核，也可改判 |
| 建议拦截 | 审核工作台，状态「待审核」+ 红色「建议拦截」 | 教务人员查看证据后人工决定 |

工作台顶部的蓝色流程说明条随时可以回看这个规则。

## 二、模拟提交申请（体验申请阶段校验）

1. 点「模拟提交申请」，可用快速填入按钮：**合规申请** / **手机号格式错误** / **重复报名**。
2. 点「提交申请」，结果区立即给出结论：
   - 格式错误或重复报名 → 红色「申请未受理 · 已在申请阶段驳回」，逐条列出命中的规则与原因；这条申请**不会进入审核系统**；
   - 合规申请 → 绿色「申请已受理」，并说明是「系统自动通过」还是「已转人工审核队列」。
3. 切到「申请受理」页可看到最近一次提交的分类统计与被驳回记录。

也可以点「导入报名表」批量导入 Excel / CSV；导入完成后弹出「通过 X 条 · 转人工 X 条 · 申请阶段驳回 X 条」的汇总。

## 三、审核一条「建议拦截」的报名

1. 在「审核工作台」用课程、状态、风险提示、审批来源或关键词筛选。想只看需要人工判断的记录，可把状态选为「待审核」。
2. 点击该行操作列的 **「查看并审核」**。
3. 弹窗从上到下依次是：
   - **申请信息**：学号、姓名、学院、专业、年级、手机号、邮箱、课程代码与名称、学分、任课教师、上课时间、报名截止、报名时间、状态、审批来源、人工复核情况、审核人/时间、申请理由、备注、审核意见；
   - **审核阶段风险提示**：命中的 R05 / R06 等规则、具体原因，以及「判定依据」（撞课课程与节次、历史修读学期与成绩）；
   - **判定依据**：该生本学期已选课表、历史修读记录表格，可自行核对「是否真撞车」「是否真的已通过无需重修」；
   - **审核轨迹**：申请受理、系统自动通过、人工操作、复核改判等全部记录；
   - **审核决定**：意见输入框与三个按钮。
4. 确认后点击 **通过 / 要求补正 / 驳回**。驳回建议写明原因，意见会写入记录与操作日志。

**规则只给「建议拦截」，不会自动驳回或通过**；这条记录的最终结论来自你在这里的一次明确点击。

## 四、人工复核 / 修改系统自动通过的结果

1. 在右上角切换为 **系统管理员**（其他身份看不到复核区）。
2. 用「审批来源」筛选「系统自动通过」，点开任意一条详情。
3. 弹窗底部出现「人工复核 · 修改系统自动通过的结果」：
   - **确认复核无误**：只标记为「已复核」，审批结果不变；
   - **改判为驳回 / 改判为待补正**：必须填写意见，系统会把该记录改为「已驳回 / 待补正」，审批来源改为「人工决定」，并在审核轨迹中留下「复核改判」记录。
4. 批量复核：勾选多条系统自动通过的记录，点底部 **批量确认复核**，二次确认后一次处理。

> 自动通过策略可以在「课程与规则」页关闭（A01）。关闭后新提交的合规申请会全部进入人工审核队列，适合需要全量人工把关的学期。

## 五、批量审核

1. 勾选列表左侧复选框，或点表头的**全选**勾选当前页全部记录（可跨页累加选择）。
2. 底部显示「已选 N 项」，点击 **批量通过 / 要求补正 / 批量驳回**。
3. 确认弹窗列出本次将处理的条数与姓名，自动排除已通过、已驳回等不适用记录；填写统一意见后点「确认执行」。
4. 批量操作在同一事务内完成，若其中一条不合法，整批回滚并提示原因。

## 六、申请受理页与导出

- **最近一次受理结果**：提交行数、申请阶段驳回、系统自动通过、转人工队列、数据约束错误。
- **申请阶段驳回台账**：登记时间、学号、姓名、课程、来源、驳回原因。点「导出驳回清单」生成 Excel，交申请人修正后重交。
- **导出通过名单**：生成多工作表 Excel —— 「通过名单」（含审批来源、是否人工复核、复核人）+「统计摘要」（各课程容量、受理数、系统自动通过、待人工审核、建议拦截、已复核）。
- **下载模板**：Excel 模板含「填写说明」工作表，写明哪些情况会在申请阶段被驳回。

演示模式（preview.html）导出的是 CSV 样例，完整 Excel 导出请启动服务后使用。

## 七、课程与规则

切到「课程与规则」页：

- 上半部分：每门课程的容量、上课时间、受理数、系统自动通过数、待人工审核数与截止时间；
- 下半部分：规则按 **① 申请受理关口 / ② 审核阶段 / ③ 系统策略** 三组展示，只有**系统管理员**可以启停，修改会记入操作日志。

| 规则 | 阶段 | 作用 |
|---|---|---|
| R01 必填字段完整 | 申请受理 | 字段漏填当场驳回 |
| R02 联系方式格式 | 申请受理 | 手机号 / 邮箱格式错误当场驳回 |
| R03 重复报名检测 | 申请受理 | 同一学号重复报同一门课当场驳回 |
| R07 课程代码与报名时效 | 申请受理 | 课程不存在、未开放或逾期当场驳回 |
| R05 上课时间冲突 | 审核阶段 | 建议拦截，转人工并附课表证据 |
| R06 已通过课程重复选修 | 审核阶段 | 建议拦截，转人工并附历史成绩；曾修未通过不拦截 |
| R04 课程容量提示 | 审核阶段 | 需留意，默认关闭 |
| A01 无风险自动通过 | 系统策略 | 关闭后全部申请转人工审核 |

## 八、操作日志

「操作日志」页按时间倒序展示：申请受理、系统自动通过、人工审核、复核确认、复核改判、申请阶段驳回、导入与规则调整。每行含关联报名号、状态变化、操作人与说明。点击「刷新」获取最新记录。

## 常见问题

**为什么格式错误的申请在列表里找不到？**
它在申请阶段就被驳回了，只存在于「申请受理」页的驳回台账，从未进入审核系统。修正后可重新提交。

**为什么「已通过」的记录还能改？**
系统自动通过的记录保留人工复核入口。切换到系统管理员，打开详情即可确认复核或改判；人工通过的终态记录不可再改。

**为什么看不到复核按钮？**
检查右上角身份是否为「只读访客」或「教务员小林」——复核与改判仅限系统管理员；另外该记录必须是系统自动通过且处于已通过 / 已通知状态。

**为什么点按钮没反应？**
检查右上角身份是否为「只读访客」，以及该记录是否已处于终态（已驳回、已取消）。

**想恢复初始演示数据？**
`python3 app/database.py --force`（会重建演示申请与操作日志，请谨慎用于已有数据的库）。

**端口被占用？**
`python3 run.py --port 8766 --no-browser` 换端口启动。
