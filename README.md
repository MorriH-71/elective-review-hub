# 大学选修课报名审核系统

一个面向教务场景的轻量报名审核小系统（v2.0）。核心不是「做一个能改状态的下拉框」，而是把报名这件事拆成**两道关口 + 一个可追溯的决策机制**：

```
申请人提交 / Excel 导入
   ↓  ① 申请受理关口：字段、格式、重复、课程时效 → 不通过即当场驳回，不进入审核系统
   ↓  ② 审核阶段风险规则：上课时间冲突、已通过课程重复选修 → 标记「建议拦截」，必须人工判断
   ↓  ③ 风险规则全通过 → 系统自动通过（decision_source=system）
   ↓  ④ 管理员可随时人工复核、修改审批结果（confirm / override，强制意见 + 全程留痕）
```

## 三个关键设计决定

1. **把「机器能判的」和「人必须判的」分开。** 联系方式格式这类错误，申请人自己就能修正，不该占用教务人员时间，也不该流进审核系统；真正需要人工的是「课表撞车能否协调」「已通过课程是否确有必要重修」这类要结合学生实际情况判断的问题。
2. **自动通过 ≠ 黑箱。** 系统自动通过的每条记录都记 `decision_source=system`、写入 `intake` + `auto_approve` 两条轨迹；管理员可「确认复核无误」或「改判为驳回 / 待补正」，改判必须填意见，并把来源改为 `manual`。自动通过策略（A01）可一键关闭，退回全量人工审核。
3. **状态机 + 全量留痕 + 守住边界。** 6 个状态、显式合法转移表，审核/复核/日志在同一事务写入，批量任一非法整体回滚；只做审核内核与最小数据 I/O，不做看板、问卷分析，但预留 `/api/stats` 与 `sql/analytics.sql`。

## 规则清单（按阶段分组）

| 阶段 | 编码 | 规则 | 命中后果 |
|---|---|---|---|
| 申请受理关口 | R01 | 必填字段完整 | **当场驳回，不入库** |
| 申请受理关口 | R02 | 联系方式格式 | **当场驳回，不入库** |
| 申请受理关口 | R03 | 重复报名检测 | **当场驳回，不入库** |
| 申请受理关口 | R07 | 课程代码与报名时效 | **当场驳回，不入库** |
| 审核阶段 | R05 | 上课时间冲突 | 建议拦截 → 转人工，附课表证据 |
| 审核阶段 | R06 | 已通过课程重复选修 | 建议拦截 → 转人工，附历史成绩 |
| 审核阶段 | R04 | 课程容量提示 | 需留意 → 转人工（**默认关闭**） |
| 系统策略 | A01 | 无风险自动通过 | 风险规则全通过时系统通过；关闭则全量转人工 |

规则存于 `rule_config` 表（含 `stage` 字段区分阶段），可在界面按组启停，改规则不改代码。每条受理记录保存 `precheck_result`（JSON：命中编码、说明、判定依据 `evidence`、检查时间），详情页逐条展示。R06 特意只命中「曾修读且考核通过」的记录；曾修未通过属于正常重修，不拦截。

## 快速开始

```bash
python3 -m pip install -r requirements.txt
python3 run.py
```

浏览器会自动打开 `http://127.0.0.1:8765/`；接口文档在 `/docs`。
`python3 run.py --init-only` 只初始化数据库，`--no-browser` 不自动打开浏览器，`--port 8766` 换端口。
数据库结构升级会自动迁移（补齐新列），演示数据版本变化时自动重建，无需手动删库。

**不想启动服务？** 直接双击根目录的 `preview.html`。它是自包含静态页，内置演示数据与完整交互（模拟提交申请、全选、筛选、详情弹窗、人工审核、复核改判、批量操作、规则开关、日志、驳回台账），界面与正式版共用同一份 `static/app.js`。演示模式导出 CSV 样例，正式模式导出 Excel。

## 演示数据分布

`scripts/gen_demo_data.py` 生成 126 行申请（含学生课表、历史修读记录两个参考数据集）：

| 去向 | 条数 | 说明 |
|---|---|---|
| 申请阶段驳回 | 14 | 4 必填缺失 + 4 格式错误 + 4 重复报名 + 2 课程/时效，只进驳回台账 |
| 系统自动通过 | 100 | 风险规则全通过，可人工复核 / 改判 |
| 待人工审核 | 12 | 6 条时间冲突 + 6 条已通过课程重复选修，均带可核对的证据 |

另埋了「曾修未通过允许重修」「有课表但不撞课」的对照样本，用来说明规则不会误伤。

## 主要接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 课程、规则（含 stage）、账号、指标、字典 |
| GET | `/api/enrollments` | 多条件筛选 + 分页（含 `source=system/manual/undecided/rechecked`） |
| GET | `/api/enrollments/{id}` | 完整申请信息 + 风险提示 + 课表/历史证据 + 审核轨迹 |
| POST | `/api/applications/submit` | 模拟申请人提交，当场返回受理或驳回结论 |
| GET | `/api/application-rejections` | 申请阶段驳回台账 |
| POST | `/api/enrollments/{id}/review` | 单条人工审核 |
| POST | `/api/enrollments/batch-review` | 批量审核（同事务） |
| POST | `/api/enrollments/{id}/recheck` | 管理员复核 / 改判系统自动通过的结果 |
| POST | `/api/enrollments/batch-recheck` | 批量确认复核 |
| POST | `/api/enrollments/import` | 上传 Excel / CSV，返回受理/自动通过/人工/驳回分类报告 |
| GET | `/api/courses`、`/api/rules`、`/api/operation-logs` | 课程、规则、操作日志 |
| PATCH | `/api/rules/{code}` | 启停规则（仅管理员） |
| GET | `/api/exports/approved-list.xlsx` | 通过名单（含审批来源、复核状态，多 sheet） |
| GET | `/api/exports/gate-rejections.xlsx` | 申请阶段驳回清单 |
| GET | `/api/stats` | 预留给下一迭代看板 |

## 实现要点

| 环节 | 实现方式 |
|---|---|
| 业务建模 | 两阶段受理、可解释的风险提示、自动决策可复核 |
| 数据库 | 原生 SQL 建 9 表 3 视图，使用 JOIN / 条件聚合 / 窗口函数 |
| 数据处理 | pandas 清洗（缺失时自动回退标准库）、openpyxl 生成报表 |
| Web 接口 | FastAPI REST + 自动生成的接口文档 |
| 表格 I/O | 模板下载、批量导入、多 sheet 名单与驳回清单导出 |
| 稳定性与数据安全 | 事务、状态约束、脱敏数据、三角色权限、全量留痕 |
| 测试 | 37 个自动化测试用例，覆盖规则、状态机、事务与导入导出 |
| 文档 | README + 需求与设计说明 + 用户操作手册 |

## 数据与隐私

所有姓名均做掩码处理，邮箱使用示例域名，手机号与学号均为虚构数据；项目不含任何真实个人信息，也不发送真实邮件或通知。
